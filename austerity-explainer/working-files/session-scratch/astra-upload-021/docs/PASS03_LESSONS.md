# Evidence-led scene workflow, historical 0.1.2

This is a manual decision guide distilled from hash-bound scene reports. The
add-on worker verified the cited report identities; it did not repeat their
production renders or independently re-judge the art. Exact scopes/statuses are
in data/lessons.json. The original 0.1.2 source bundle includes its reports under
qa/v0.1.2/evidence. In 0.1.4, use the current registry for copied evidence paths;
version-specific paths below refer to the frozen historical source bundle. Project
paths are provenance only, never runtime dependencies.

## Pick the failed gate before choosing the edit

- Pigment: material-specific marks, shape, scale, direction and repeat.
- Response: shader/normal/roughness behavior under stated inputs.
- Scene: real illumination, reflections, atmosphere and explicitly artistic depth.
- Whole image: light/dark masses, warm/cool relationship, depth/edge loss and
  people/setting coherence against the original reference.
- Evidence/construction: actual evaluated support/clearance, scoped preservation,
  source/scene/image identity and delivery.

Passing one does not pass the others. A real scattering domain can still look like
a white veil; a genuine reflection can still be an awkward solid cyan patch.

## Illumination → source coverage → optical depth

1. Freeze geometry, maps, camera and air. Record actual emitter position/aim,
   shape/size, power and normalization. Check what a wet surface can reflect.
2. Measure controlling attribute occupancy/range before changing a roughness
   endpoint. A labelled parameter can barely affect pixels if values never reach it.
3. Compare one source-direction/coverage change. Inspect both relevant views;
   verify the intended target is actually in-frame before taking its pixel samples.
4. Only then compare bounded participating air separately. Record metric domain
   extent, density/spatial profile, phase/absorption choices and volume bounces.
   Path length changes optical depth; a density value alone is not portable.
5. Reject a veil that erases architecture. Keep rejected thick-air/high-power
   studies so a later reviewer does not prescribe them again.

Pass03 factory/mine have scoped independent art acceptance. Street’s broad cool
wet grouping also passes; the cited remaining lamp-local clause has its own
bounded study. None of these scene values becomes an add-on preset.

## Visible sky, fill and ray policy

World-direction painted sky colour, glossy sky gain and diffuse environment fill
have separate ownership. Record each actual saved branch and map/seam contract.
A deliberate ray-specific power split is artistic direction, not neutral equal
radiance. Test sky pigment first, then fill/ground air separately if needed.
An artistic world-space depth palette is also distinct from physical scattering.

A new negative test is particularly important: in the tested Blender 5.1.2 Cycles
street path, stored Light.transmission_factor/volume_factor changes produced exact
zero decoded FLOAT32 RGBA difference in both hero and oblique. RNA presence,
range and readback therefore do not qualify those fields as effective controls
for this path. This is not a claim about every engine/version. A separate
object-ray-visibility/co-located-power implementation changed the original target
core in its actual hero diagnostic. That original target was offscreen in the fixed
oblique; the negative-index sample was invalid. The corrected shared-view study
remains experimental and requires its own complete render/art evidence. No such
control is added by 0.1.2. The source bundle preserves the exact target correction
report as qa/v0.1.2/evidence/object_ray_target_correction.md, SHA256
055039932ad74247c03f1ffef599650cfb524c99a520c544833ca1f59d83dee3.

## Coordinate ownership and physical support

Record the field owner, space, units, bind transform and rebind conditions:
rest-local response, world-XY floor wear, Generated-box factory air, world-direction
sky, fixed world-axis depth and pose-local cloth are different contracts. Camera
independence does not establish arbitrary-transform or animation invariance.

Synchronize the evaluated view layer before bounds/triangle tests. Paint overlays
and verified Surface-less, nonemissive volume envelopes are not physical supports.
Keep air domains participating in rendering; exclude only the verified nonphysical
objects from support attribution. Hidden-overlay changes require replay against
remaining physical geometry even if vertex arrays are unchanged. Support, passage
clearance, coplanarity and collision checks answer different questions.

## Exposed joints and authored marks

The shoji study isolated two mechanisms: exposed rail/stile faces, and overlapping
fixed/parked paper. Bounded face inset addressed one; coherent parked-assembly
separation addressed the other. The report records 22 rails, 44 contacts, seven
named rays and a paper gap. Those measurements are scene examples, not global
repair defaults. Preserve true support and doorway clearance; do not conceal
geometry defects with shaders or shrink every beam.

Authored masks may still read as polygon decals. Judge lost/held edges, tail shape,
physical scale and repeat in actual views. Pine variation must change envelope,
profile and internal division; scales/rotations alone may preserve the same packet.
Keep woody scaffold and read-throughs visible in two relevant cameras. Quiet finite
Cartesian cloth passages removed the specific wrapping-band defect without
changing normals or anatomy. None is a universal material-authoring adapter.
Japanese v13’s earlier critic accepted narrow plaster,
pine, daylight/depth and named shoji criteria, but the user subsequently rejected
the scene’s completion/reference closeness. That art verdict is superseded;
the local improvements do not establish a finished Japanese style. Its world-Y depth palette
intentionally changes pine bark graphs as well as foliage graphs. Preserved wood
geometry/attributes must not be described as unchanged material graphs.

## Finite closure

Before editing, check whether the ledger covers the user’s whole-image goal; then
write the current criterion, target/views, preserved wins, blocking remainder,
allowed test, required evidence and stop condition. Avoid arbitrary detail inflation
after adequate criteria pass. However, explicit user rejection or broader reference
mismatch can invalidate the ledger itself. Japanese v13 is this counterexample:
prior critic completion did not satisfy the user. Retain that report as superseded,
reopen holistic style assessment, and keep measured technical facts separate.
A critic pass is never a substitute for user approval.

User-directed scene work should have verified Blender MCP access and consider
procedural generation and Geometry Nodes where appropriate. Tool/API readback
and evaluated/rendered behavior still require separate checks. This guide does
not add a Geometry Nodes preview adapter or execute those tools.

The registry separates source-example art acceptance from measured behavior and
new-application review. All built-in non-neutral preset values remain unchanged
and experimental. Recipes never execute code or authorize scene changes.
