# Calculators: the hand-found numbers, worked out automatically

What this folder is: small tools that work out, from a new film's own files, the numbers this project found by trial
and error over 35 logs: where a prop lands on the phone frame, how far away the camera may stand, how long a slide may
be before the painting goes soft, how long a label is readable, what a painting will cost, how long filming will take,
and about 400 more. Each tool says which house numbers it used, and every house number lives in one table,
`kit/film-settings.json`. One command, the **preflight**, runs the right tools at each stage of making a film and stops
the paid or long step that follows when something new is wrong.

Nothing here spends money or calls a paid service. Every tool answers `--help`, opens with a plain note ("What this
does: ..."), prints a plain report naming the settings it used, and takes `--json`, `--out FILE`, `--report FILE` and
`--settings FILE`. Plain Python 3 with numpy, OpenCV and Pillow; node for the page tools; Blender only for the tools in
`paper-film/blender/`.

## The preflight: one command per stage

```
plugins/explainer-film/bin/explainer-film-preflight STAGE [--project DIR] [--plan FILE] [inputs ...]
```

(or `python3 kit/calculators/preflight.py STAGE ...`; `--kit DIR` or `EXPLAINER_FILM_KIT` runs an installed kit's copy).

| Stage | When | What it runs | What it guards |
|---|---|---|---|
| `script` | before recording | `lint_script.py before` (cue, capitals, names, sentences, figures a minute, the main rule twice, the key page, out-of-date facts), the estimated timeline, the voice's credits and dollars, `plan_budget.py ledger` | the paid recording |
| `record` | after recording | `lint_script.py after` (a cue read aloud, words and names heard wrongly, silences, late words, pages to record again), `sound_gates.py voice` and `mouth` | using the recordings (a re-record is paid) |
| `shots` | before building or drawing a place's views | `place_facts.py check`, `plan_shot.py --strict` (each view, or the shot list), `view_audit.py audit`, `plan_effects.py wind` (when the place has chimneys), `plan_lights.py plan` (each view), `plan_states.py plan` (with a state plan), and each view's check file (kinds of shot, figures, accepted list) | building and rendering the views and plates |
| `plates` | before paying for paintings | `plan_lights.py render-log`, the shot checker's report (new problems only), `paint_request.py preflight` and `price`, `model_lint.py` (with `--models`), `plan_budget.py ledger` | the paid paintings |
| `paint` | after each painting arrives | `after_painting.py check` (line-up, figures, skin, style, the behind painting, kept shadows) | using the painting |
| `pages` | while building pages | `plan_page_timing.py check`, `check_page_layout.mjs`, `camera_audit.py` (with `--camera-log`), `plan_effects.py lint` (with `--paper-pages`); `page_events.mjs` first with `--scene S --make-events` | filming those pages |
| `film` | before filming | a critique newer than every page file with each finding fixed or accepted; a passed pages report newer than every page file; `plan_budget.py filming` (time, workers, pieces, memory, disk) | the long filming run |
| `finish` | after finishing | `sound_gates.py loudness`, `length` and `alignment`, the sendable size, `plan_budget.py push`; `find_jumps.py` with the planned cuts (from the newest pages report, or `--planned-cuts`), when the memory allows (it keeps every frame: about 10 GB for a 4.5-minute film; `--jumps` tries anyway) | sending or publishing |

**How a report reads.** The report goes to `PROJECT/preflight-reports/preflight-STAGE-DATE-TIME.md`, the same as `.json`,
and a folder of that name holding every tool's own JSON and plain output. Its first two lines say everything:

```
Preflight script (before recording the narration): FAIL. 1 to fix, 11 to look at, 0 known and accepted, 0 input(s) missing; 2 check(s) in 0.3 s.
Paid step BLOCKED: recording the narration with the voice service (about US$1.10: 6,287 credits: one per letter sent, the cue included; US$19.15 left of the allowance "full redesign"). First fix the failures below (or accept them, with who and when), then run this stage again.
```

Then: **Inputs missing** (each with the option, what the file is, and the exact command or skill that makes it),
**To fix** (blocks), **To look at** (a person decides; does not block), **Known and accepted** (kept on purpose; does
not block), **Inputs not given** (the stage ran but checked less), **Cost and time**, **Checks run** (each tool, its
version, exit, seconds and the exact command), and **Inputs** with their sha1. Exit 0 pass (perhaps with things to look
at), 1 fail, 2 an input is missing.

- **Known and accepted problems.** A view's check file and a place's facts file carry an `accepted` list; the
  preflight plan (or `--accepted FILE`) can carry more: `{"stage", "check", "text", "page" or "view", "reason", "who",
  "date"}`. An entry without `who` and `date` is not used. Only new failures block. A kept problem that has grown worse
  than it was accepted at fails again.
- **Inputs hashed.** Each input is hashed when first read and again at the end. A report whose inputs changed while
  it ran is STALE (blocked). Each tool is named with its version (the first 8 letters of its file's sha1).
- **The gate.** `explainer-film-preflight STAGE --gate` runs nothing: it opens (exit 0) only when the newest report of
  that stage passed and every input is unchanged since. A script about to start a paid or long step can call it.
- **A preflight plan** (`PROJECT/preflight-plan.json`, or `--plan FILE`) names a film's files once for every stage;
  print an example with `--example-plan`; `--list` prints every stage's inputs and which tool makes each.
- **Paid steps still need the user's own yes.** A passed preflight only says the step is ready to ask about.

**Shot-kind profiles** (in film-settings.json). The notice corner's rules were measured on one still life; the Works'
accepted views break them. Each view names its **kinds of shot**, and the profile relaxes only what that kind needs
(the loosest wins when a view names several): **still_life** (the base, from the picture the user liked, log 30);
**crowd** (a story box up to 0.80 wide; rule 4 between figures replaced by head spacing; story things may cover 2% of the
bottom-left; a dark band instead of "titles in sky"); **overview** (a wider eye range; a fill prop may make the reach);
**interior** (props rest on declared surfaces such as a counter; eye 1.5-1.7 m; provisional); **dark_subject** ("subject
brightest" and "lit from below" off, replaced by a silhouette contrast of at least 2.2). A written order says which rule
wins when rules conflict (camera first, the quiet side's weight last).

## Tips for a model making a film

The full guide is `../docs/LLM tips and tricks.md` (every tip names the tool that checks it, by stage). The short list
here is the part that concerns these tools. Run the stage's preflight first and read its report before doing anything by
hand. Each tip names the tool that checks it.

**How to work**
- Compute before you render: `frame_geometry.py project` or `boxes` answers in a second where a thing lands. Let the shot checker confirm on the render; boxes are upright, so a turned thing comes out a little wider than it renders.
- One change, then measure again. A camera fix moves everything: fix the camera first, then props, then light.
- Quote the measured numbers in every report, never "looks fine". Treat an **invented** setting as a guess and say so when a result rests on it.
- Change a house number only in `film-settings.json`, with its kind and source.
- A "look" is a person's call; a "fail" blocks; "known" was accepted by someone, with a date. Never accept a problem yourself: write who accepted it.

**Script and voice** (`script`, `record`)
- One identical cue on every page; no capitals; names respelled in English sounds; sentences of about 9 words; at most about 4 spoken figures a minute; the main rule said twice, word for word; mark the key page `"key": true` and give it a slower page (`lint_script.py`).
- A guess needs a 4 s hold; a "..." is not thinking time (`lint_script.py`).
- Estimate the timeline from an earlier recording of the same voice before paying, and build the pages on it (`lint_script.py --word-times`).
- Download recordings at once; judge the voice by numbers and re-record only the pages the gate lists (`lint_script.py after`, `sound_gates.py voice`). Record every page before filming: a late retake moves every page after it (`plan_page_timing.py refilm`).

**Places, cameras and composition** (`shots`)
- Plan the camera with `plan_shot.py` before building a view and judge it again before rendering: the reach, the 6 m rule, the crowd's axis and the slide limit are sums, not tries.
- Stand where a person would (1.5-1.9 m up), in line with the subject's edge. Turn once to place where the lines meet, then only slide; close a gap by sliding, never by turning (`plan_shot.py`, `camera_audit.py --built-set`).
- Measure reach above the surface a thing stands on (the counter, not the floor). On a level street the lines meet at 0.5 down.
- A slide magnifies the **nearest painted** thing most (the notice corner's pail 1.45x against 1.30x for the notice). Draw the plate 4 degrees wider from the slide's start (`frame_geometry.py slide`, `plan_shot.py`).
- Put a view's kinds of shot, its figures and its accepted problems in its check file (`kind_of_shot`, `figures`, `accepted`; see `examples/`), so a kept shot is reported as known, not failed every time. Write the check file with `make_check_file.py`; write by hand only the story roles.
- People: backs to the camera at 6 m or more; a crowd across the view, two deep, heads a head width apart. Never answer a face that shows with a black silhouette: turn the figure away, or give the painter "face lost in shadow" and check the head after painting (`plan_shot.py`, `paint_request.py`, `after_painting.py`).
- Lettering is ours, on its own surface. Words the page needs at 20 px or more; turn drums toward the cameras that read them; dim a readable sign the narration never names; letter the back of a board that shows from behind (`view_audit.py`).
- Smoke blows across the view; trace it on every view before filming; drop smoke that never enters the frame (`plan_effects.py wind`).
- Lights: the subject's own narrow key light; watts from distances; cut a light's reach before its strength; only a few cast shadows; a dark subject stands against a lit background (`plan_lights.py plan`).

**Plates and paintings** (`plates`, `paint`)
- Run `model_lint.py` on every model and on the dressed scene before any plate: a stripe, a floor 2 cm over the ground or glass reading its picture's alpha costs a repaint once painted.
- Read the render log before judging any light; a "Shadow buffer full" plate is refused (`plan_lights.py render-log`).
- Fix every plate preflight failure in 3D, not in the prompt: the painter copies the plate's light and dark, lifts a glowing hollow into a band, reads a black opening as open, smears thin parts and leaves people's long shadows (`paint_request.py preflight`).
- Write each story prop's `paint_as` words; never write the rest of the prompt by hand. Say every person: how many, near or far, which way they face (`paint_request.py prompt`).
- Quote the price as an estimate (dated rate x megapixels out and in) and ask the user before every paid call (`paint_request.py price`, `plan_budget.py ledger`).
- Run `after_painting.py check` on every painting as it arrives and keep the PNG it writes. Figures painted paler than in the plate read mid-grey on a phone: darken them back.
- Plan held-shot changes with `plan_states.py`: one plate per change on its own word; nothing changes during a slide; something besides the people changes at a cut.

**Pages and timing** (`pages`)
- Run `page_events.mjs`, then `plan_page_timing.py check` and `check_page_layout.mjs` on every page before filming it; run them again on the real timeline once the narration is in.
- Always give `kit.at('word', n)` the time it is said when the word is said more than once on the page.
- A label up for under a second before a cut cannot be read: bring its words in with the line, start it on an earlier word, or move the cut. A conclusion starts on the first word of its clause.
- Anything that ends on a cut gets `fadeOut: 0`. A new line in the same place starts only after the old one has gone.
- Never pick still times by eye: use the stills command the timing check prints (times separated by spaces, one run, so page turns are right).
- Return `still: false` while the camera moves and a held-shot key whenever it holds; set every effect from the moment alone.

**Filming and finishing** (`film`, `finish`)
- Before filming, get a fresh critique of every page and mark each finding fixed or accepted (with who and when); the film stage refuses an older critique.
- Film a short profile first (`plan_budget.py profile-commands`, then `measure`) and plan from it; tell the user the time before starting. Stretches under 2 hours; stop a job by its own process number, never with `pkill -f`.
- Measure lengths after each audio step and the loudness on the encoded copy; run `find_jumps.py` with the planned cuts (the `finish` stage does when the memory allows).
- Never push audio, video, keys or files over the size limits (`plan_budget.py push`).

## What the tools cannot judge

A person (or a fresh critic followed by a skeptic) decides these; the tools only supply numbers and pictures: whether
a detail reads as something else at phone size; period and story accuracy of pictures; whether motion matches the
meaning of the words; whether machines read as machines; whether a hero prop has enough detail; research honesty (a
rule scoped exactly to its evidence, one word one meaning, whose words stand behind "they say"); what a newcomer
understands; whether a time cut where people vanish reads as time passing; whether a picture contradicts a card beyond
the small table; colours and symbols with political or commercial meaning; the story choices (place, era, mood, the
subject, the story props, each prop's `paint_as` words); whether a painting looks painted enough; the mood of a
soundtrack stretch; which rule wins in a real conflict (a dark iron gate cannot be the brightest thing); the overall
feel of the light; and whether a flagged near-touch, thin part or small sign is worth fixing. **Paid steps need the
user's own clear yes; a vague reply is not a yes, and a refusal is never worked around.**
